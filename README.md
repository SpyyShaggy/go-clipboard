# LAN File Share & Clipboard Hub (LAN Drop)

Легковесный, быстрый локальный сервер обмена файлами, медиа, папками и текстом в локальной сети (LAN / Wi-Fi), написанный на Go без сторонних внешних зависимостей.

---

## ⚡ Особенности

- 📦 **Потоковая загрузка (Direct Stream)**: файлы любого размера (видео 4K, образы, архивы) пишутся на диск напрямую чанками без переполнения оперативной памяти.
- 📁 **Отправка папок (Folder Upload & Auto-ZIP)**: поддержка Drag & Drop и выбора целых папок любого уровня вложенности. Папки автоматически упаковываются в `.zip` прямо в браузере на клиенте (без интернета и сторонних тяжелых библиотек).
- 📋 **Быстрый буфер обмена**: отправка текста, ссылок и сниппетов в один клик с автосохранением в `.txt`.
- ⏳ **Автоматическая очистка (Auto-cleanup)**: файлы, сообщения и временные фрагменты перманентно удаляются по истечении заданного времени (по умолчанию 1 час), предотвращая засорение накопителя.
- 💻 **Кроссплатформенность из коробки**: автоматическое определение рабочей директории на Linux, Windows и macOS; поддержка гибких флагов запуска `-dir`, `-port`, `-ttl` и переменной окружения `SHARE_DIR`.
- 🛡 **Безопасность путей**: защита от Path Traversal (`filepath.Base`), санитизация небезопасных символов в названиях файлов, предотвращение коллизий (автоматическое инкрементирование `file (1).ext`).
- 📱 **Адаптивный UI**: встроенный веб-интерфейс в тёмной теме, оптимизированный под мониторы ПК, планшеты и смартфоны.
- 🚀 **Минимализм**: стандартная библиотека Go, нулевые внешние зависимости, компиляция в один самодостаточный бинарный файл.

## 🛠 Требования

- **Go**: версия 1.20+ (протестировано на Go 1.22+ / 1.24+)
- **ОС**: Linux (Arch, CachyOS, Ubuntu, Debian, Fedora), Windows 10/11, macOS

## 🚀 Сборка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/SpyyShaggy/go-clipboard.git
cd go-clipboard
```

### 2. Сборка бинарника

- **Linux / macOS**:
  ```bash
  go build -o lanshare first-local-site.go
  chmod +x lanshare
  ```
- **Windows** (в PowerShell или CMD):
  ```cmd
  go build -o lanshare.exe first-local-site.go
  ```

### 3. Флаги запуска и настройка папки

Сервер автоматически определяет каталог для сохранения файлов:
1. Если задан флаг `-dir` — используется он.
2. Иначе, если задана переменная окружения `SHARE_DIR` — используется она.
3. Иначе, если существует `/mnt/game/site` (Linux) — используется этот путь.
4. Иначе автоматически создается и используется папка `Downloads/lan-share` в домашней директории пользователя (или `./uploads`).

Параметры командной строки:
```text
Usage of ./lanshare:
  -dir string
        Папка для сохранения файлов (по умолчанию $SHARE_DIR или автоопределение)
  -port string
        Порт сервера (по умолчанию ":8000")
  -ttl duration
        Время жизни файлов до автоудаления (по умолчанию 1h0m0s)
```

**Примеры запуска:**
```bash
# Обычный запуск с дефолтными настройками
./lanshare

# Запуск с указанием своей папки и порта
./lanshare -dir ~/MyShare -port :9000 -ttl 2h

# Запуск на Windows
lanshare.exe -dir C:\Share -port :8000
```

После старта в консоли отобразятся доступные сетевые адреса:
```text
Сервер запущен. Порт: :8000
Папка: /mnt/game/site (TTL: 1h0m0s)
Откройте в браузере:
  http://192.168.1.15:8000/
```

## 💻 Развертывание на Windows и macOS

### Использование на Windows
1. Соберите или скопируйте `lanshare.exe`.
2. Запустите `lanshare.exe` двойным кликом или из терминала.
3. **Брандмауэр Windows (Важно!)**:
   При первом запуске Windows Defender Firewall покажет предупреждение:
   - Обязательно отметьте галочку **«Частные сети» (Private networks)**.
   - Нажмите **«Разрешить доступ» (Allow access)**. Без этого другие устройства в локальной сети не смогут подключиться к порту 8000.
4. Откройте выведенный IP-адрес (например, `http://192.168.1.x:8000`) в браузере любого устройства в той же сети.

### Использование на macOS
1. Соберите бинарник: `go build -o lanshare first-local-site.go`.
2. Запустите: `./lanshare`.
3. При запросе macOS на разрешение входящих сетевых подключений нажмите **«Разрешить»**.
4. Узнать IP-адрес Mac можно в *Системные настройки → Сеть* или командой `ipconfig getifaddr en0`.

## 🌐 Использование вне домашней сети (через Интернет)

Если сервер запущен на одном компьютере (например, дома), а вы хотите отправлять или скачивать файлы с телефона через 4G/LTE или из другой сети (на работе / в поездке):

### Вариант 1: Tailscale (Рекомендуемый, самый простой и безопасный)
Не требует белого IP, роутера и проброса портов:
1. Установите [Tailscale](https://tailscale.com) на компьютер с сервером и на мобильные устройства / ноутбуки.
2. Войдите в единый аккаунт на всех устройствах.
3. Компьютер получит постоянный защищенный IP в вашей личной сети (например, `100.85.12.34`).
4. Открывайте `http://100.85.12.34:8000/` с любого устройства в любой точке мира.

### Вариант 2: Cloudflare Tunnel (Публичный доступ без открытия портов)
Позволяет получить безопасную публичную ссылку:
```bash
# Установка cloudflared и запуск туннеля к вашему порту:
cloudflared tunnel --url http://localhost:8000
```
В терминале появится временная ссылка вида `https://xxxx.trycloudflare.com`, которая будет открываться на любом устройстве в мире.

### Вариант 3: Проброс портов на роутере (Port Forwarding)
Если у вашего провайдера есть статический или динамический «белый» IP-адрес:
1. Зайдите в панель управления домашним роутером.
2. Настройте проброс входящего порта `8000` на локальный IP компьютера (например, `192.168.1.15:8000`).
3. Подключайтесь по вашему внешнему IP: `http://ВНЕШНИЙ_IP:8000/`.

## ⚙️ Автозапуск через Systemd (Linux / Arch / CachyOS)

Для запуска в фоновом режиме от имени обычного пользователя (без root):

1. Создайте директорию сервисов:
   ```bash
   mkdir -p ~/.config/systemd/user
   ```
2. Скопируйте файл юнита:
   ```bash
   cp lanshare.service ~/.config/systemd/user/
   ```
3. Активируйте и запустите:
   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now lanshare.service
   ```
4. Управление сервисом:
   - Перезапуск: `systemctl --user restart lanshare.service`
   - Логи: `journalctl --user -u lanshare.service -f`
   - Статус: `systemctl --user status lanshare.service`

Чтобы сервис работал даже при завершении сеанса пользователя:
```bash
loginctl enable-linger $USER
```
